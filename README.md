# Agent Bench Matrix

エージェント向けベンチマークの公開リーダーボードを集めて、モデル・エージェントごとに一枚の表にまとめたものです。

**公開ページ:** https://o6lvl4.github.io/agent-bench-matrix/

## 何が見られるか

| 表示 | 内容 |
|---|---|
| マトリクス | 行がモデル、列がリーダーボードの表。セルはそのモデル単体で走らせた行のうち最良の値。押すと該当する全行(エージェント・設定・日付・検証マーク・出典)が出る。分野・オープンウェイト・載っている表の数で絞り込み、列名で並べ替え。実測のない枡には、薄い字の `~` 付きで推定値を入れる(切り替え可) |
| 戦闘力(推定) | モデルごとの実力を1つの数にしたもの。総合と分野別、誤差と実測数つき。**ボードが公表した数字ではなく、実測から当てはめた推定** |
| 自己申告 | どのボードにも載っていないモデル(例: Sakana Fugu)について、出した側が公表した数字。マトリクスでは `†` 付きの別色。**ボードの数字ではなく、当てはめにも入れない** |
| ベンチマーク | 表ごとのカード。何を測るか、タスク数、指標、走らせ方、注意点、リーダーボード・論文・取得データへのリンク |
| 表 | 1つのリーダーボードの全行。費用や試行別の値など、ボードが出している他の列もそのまま |
| 取れなかった表 | 探したが機械的に取得できなかったボードと、その理由 |

状態は URL に入るので、絞り込んだ画面をそのまま共有できます。

## 数字の扱い

- **数字はすべて、各リーダーボードが公開しているデータを取得し、スクリプトで取り出したもの**です。記憶・要約・ベンダーの発表文から書いた数字は入れていません。
- 取得した元データは `sources/<表のid>/` に置き、各表の `snapshot` から辿れます。
- 取れなかった表は推測で埋めず、`data/gaps/` に理由付きで残します。
- **比べてよいのは同じ表の中だけ**です。スコアはモデル単体の性質ではなく、モデルと足場(エージェント・試行回数・推論量)の組の性質で、同じベンチの名前が付いていてもボードが違えば走らせ方が違います。HAL の GAIA と公式の GAIA が別の列になっているのはそのためです。
- 複数のモデルを組み合わせたシステムの行は、どのモデルの値とも言えないのでマトリクスには入れず、表の画面にだけ出します。
- 検証マーク・日付・提出者・オープンかどうかは、ボード自身が示しているものだけを写しています。自己申告の行も含まれます。

## 自己申告

ボードに載っていないモデルは、ボードの数字では並べられません。それでも見たい場合のために、出した側(ベンダー)が公表した数字を `data/claims/` に**別の層**として置きます。ボードと同じ規律で扱います: 元の文書を取得し、機械的に取り出し、取り出した部分を `sources/claims/` に保存し、どの表に対応づけてよいかを1件ずつ決めます(集合や版が分からないものは対応づけません)。画像でしか公開されていない数字は入れません。ページでは `†` 付きの別色で出し、押すと出した側・走らせ方・元の文書が見えます。戦闘力の当てはめには入れません。

## 推定(戦闘力)

実測は歯抜けです。どのモデルもすべての表に載っているわけではないので、そのままでは「このモデルはどのくらい強いのか」が読めません。そこで、実測されたセルだけから1本の軸を当てはめます。

```
z(表, モデル) ≒ b(表) + s(表) × a(モデル)
```

`z` は表ごとに標準化した実測値(高いほど良い向きに揃えたもの)、`a` がモデルの実力、`s` はその表が実力差をどれだけ広げて見せるか、`b` はその表の水準です。`a` と `(b, s)` を交互に最小二乗で解き、`a` を平均50・標準偏差10に直したものが「戦闘力」です。分野ごとにも同じ当てはめをします。

- 実測が3モデルに満たない表と、全員が同じ値の表は、順位を語らないので使いません。
- 実測の少ないモデルは、説明できなかった残差の大きさに応じて真ん中へ寄せます(縮約)。1回の結果だけで上位に来ない代わりに、誤差が大きく出ます。
- 空きセルの推定値は、その分野の当てはめをその表の目盛りに戻し、そのボードが実際に見た範囲に収めたものです。
- **これは推定であって実測ではありません。** ページでは書式を分け、データでも `fit` として実測の表とは別に置いています。`data/tables/` に推定値が混ざることはありません。

## データ

```
data/tables/<id>.json   1つのリーダーボードの表(メタデータ + 全行)
data/gaps/<id>.json     取れなかった表と、その理由
data/claims/<id>.json   自己申告(出した側が公表した数字)。ボードの数字とは別の層
data/models.json        モデルIDの登録簿(表示名・ベンダー・オープンウェイトならその配布先・ボードごとの表記揺れ)
sources/<id>/           取得した元データ(自己申告は sources/claims/<id>/)
docs/                   GitHub Pages で配信するページと、ページが読む data.json
src/build.almd          検査して docs/data.json を書くツール(Almide)
src/fit.almd            戦闘力の当てはめ(Almide、テストつき)
```

形式は [DATA.md](DATA.md) にあります。

## 更新

```bash
# data/tables/ を更新したら
almide run src/build.almd -- --strict
```

出典URLの欠落、形の崩れた日付、取得日より後の日付、行の日付と合わない `newest_row_date`、登録簿に無いモデルID などがあると、問題を列挙して終了コード 1 で止まり、`docs/data.json` は書き換えません。CI も同じ検査を走らせ、コミットされた `docs/data.json` がデータから作ったものと一致するかを確かめます。

誤りに気づいたら、あるいは載せるべきボードがあれば Issue か PR をください。

## ローカル実行費用（試算）

「実行費用」タブ（`#/cost`）は、登録済みモデルから選んで、検証できた量子化ファイルのサイズ・KVキャッシュ・仮の実行余裕を積み上げる別の層です。戦闘力の一覧から各モデルへ移動できます。重みが非公開のモデルや未調査のモデルには値を捏造しません。

- **メモリに収まりそうかの試算であり、起動・速度・ベンチマークスコアの再現を保証しません。** 最小側と余裕側は異なる安全率で、実測の最低動作構成／推奨構成ではありません。
- 単一GPUまたは単一統合メモリ機を対象とします。GPUを複数足したVRAMの単純合算やCPUオフロードは対象外です。GPU単体価格にはホストPC代を含みません。
- 価格は特定SKUの公開ページから確認した税込／送料条件付きの観測価格で、相場全体の最安値や購入時の在庫を保証しません。価格グラフは実際の観測・公開履歴のみです。記録が足りなければ不足を表示します。
- 電気代はユーザーが編集する消費電力・時間・単価からの計算です。機種の実測電力や現行の電力料金ではありません。
- `data/cost.json` と `sources/cost/` はベンチマークの実測値から分離し、`scripts/build_cost.py` が検査して `docs/cost-data.json` を作ります。自動取得ジョブや有料APIは追加していません。

```bash
python3 scripts/build_cost.py
python3 scripts/build_cost.py --check
python3 -m unittest discover -s tests -p 'test_*.py'
npm ci --ignore-scripts
npm test
```

価格の再確認時は、取得日付きの新しいスナップショットを `sources/cost/prices/snapshots/` に追加し、過去のファイルを上書きしません。モデルと価格は別々に更新できます。取得後のオフライン再生成は次の順です（ネットワークアクセスはしません）。

```bash
python3 sources/cost/models/extract_profiles.py
python3 sources/cost/prices/extract_model_cost_prices.py
python3 scripts/assemble_cost.py
python3 scripts/build_cost.py
```

CI は保存した証拠からの再生成結果、価格・モデルのスキーマ、計算と DOM の回帰テストを検査します。実機でのモデル実行テストは含みません。
